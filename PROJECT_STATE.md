## 4. Key Architectural & Design Decisions

1. **Thin Routes Pattern:** `src/app/` files contain only 5–10 lines re-exporting real screens from `src/screens/`. Zero business logic or layout styling in routes.
2. **Obsidian Deep-Space Instrument Aesthetic:**
   - Backgrounds: True void black (`#04050A`), deep surface (`#0B0D14`), elevated surface (`#131622`).
   - Hairline borders: `rgba(255, 255, 255, 0.08)`.
   - Core Accent: Event Horizon Amber (`#F5A623`) for depth 0 ("Me").
   - Cosmic Tiers:
     - Depth 0 (Core): `#F5A623` (Event Horizon Amber)
     - Depth 1 (Galaxy): `#818CF8` (Nebula Indigo)
     - Depth 2 (Solar System): `#38BDF8` (Stellar Sky)
     - Depth 3 (Planet): `#2DD4BF` (Orbital Teal)
     - Depth 4+ (Moon): `#94A3B8` (Lunar Silver)
   - Platform monospace font (`Menlo` on iOS, `monospace` on Android) for technical metadata and paths.
3. **Database Architecture & Migration Flow:**
   - SQLite self-referencing hierarchy (`parent_id REFERENCES nodes(id) ON DELETE CASCADE`).
   - Self-referencing column typed as `AnySQLiteColumn` to satisfy strict TypeScript recursion check.
   - Foreign keys enforced explicitly via `expoDb.execSync('PRAGMA foreign_keys = ON;');` immediately on connection in `src/db/client.ts`.
   - Both `expoDb` and `db` exported from `src/db/client.ts`.
   - Migrations handled cleanly via `useMigrations(db, migrations)` from `drizzle-orm/expo-sqlite/migrator` inside `DatabaseProvider`.
4. **Navigation:** Single-screen Explorer with `currentNodeId` in React state and hardware Android `BackHandler` interception.
5. **PR-Only Merge Policy (Rule 6):** Feature branches are NEVER merged locally to `dev`. Every completed step pushes to `origin` and opens a PR using `.github/commands/create_feature_pr.md` for manual review and merge on GitHub.
6. **Zero AI Slop & Vector Icons (Rule 7):** Banned filler status copy (`ONLINE`, `STANDBY`, `SYSTEM // CONFIG`, etc.) and banned raw system emojis for navigation chrome. All navigation icons must use `@expo/vector-icons` (`Ionicons` / `Feather`), reserving emojis strictly for user-created content.
7. **Core Contracts & Anti-Slop Constants:**
   - Core domain models established in `src/types/index.ts` (`ParsedNode`, `SearchResult`, `BreadcrumbItem`, `ExportedDatabase`, `DatabaseStats`).
   - Repository input contracts formalized: `CreateNodeInput` and `UpdateNodePatch`.
   - Starter templates (`src/constants/starterTemplates.ts`) use structured semantic categories (Food, Entertainment, Work, Study, Hobbies), themed token colors, and clean Ionicons names without raw emoji chrome.
   - Status configurations (`src/constants/statuses.ts`) cleanly map all 6 preset states to display labels, Ionicons, and token colors.
8. **Repository Engine & Recursive CTE Architecture (Step 5 Implemented):**
   - `expoDb.getAllSync` utilized for all recursive CTE queries (`getAncestors`, `getDescendantCount`, `moveNode`, `searchNodes`) with standard snake_case column aliasing (`parent_id AS parentId`).
   - `parseNode` wraps `JSON.parse` with try/catch, guaranteeing safe array/object fallbacks.
   - `moveNode` fetches full recursive descendant IDs to prevent circular nesting, and cascades depth shifts atomically via `expoDb.withTransactionSync`.
   - `importDatabase` validates version and sorts nodes `depth ASC` inside a transaction.
   - `runRepositorySelfTest` executes 8 isolated integration checks and cleans up cleanly.
